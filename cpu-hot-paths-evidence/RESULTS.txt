Individual generation results are inconclusive: their paired ranges all cross
zero, including the negative median for lookup/OpenPBR. All eight combined pairs
improved for each material. The combined median is evidence for this standalone
workload on this machine, not a consumer application prediction. Microbenchmark
gains are clear but cannot be added together to estimate end-to-end performance.
No outliers were discarded. Raw samples are in timings.csv (880 rows).

Validation

Focused baseline, each independent variant and combined: 207 assertions / 6 cases.
Combined full configured suite: 26844 assertions / 97 cases, all passed.
GLSL vertex/pixel sources for standard_surface and OpenPBR are byte-identical
between baseline and every candidate. All timing checksums also agree.
All builds/tests use the MSVC optimized Release configuration documented in
README.txt. The full suite covers enabled GLSL/Slang/OSL/MDL/MSL generators, with
rendering disabled. No GPU execution or downstream shader compiler validation.

Profiling

VTune 2026.4 software hotspots collection succeeded with usable MaterialX symbols
and user call stacks. The baseline call tree confirms all four reported functions
are exercised. The hottest self-time rows include ifstream construction (5.295 s),
GetFileAttributesA (2.532 s), malloc (1.602 s), and std::find (0.386 s). This profile
includes 1500 generations of each material and library setup; it is diagnostic,
not the timed comparison. A matching combined profile is supplied separately.
Large shader-source I/O costs help explain why isolated generation changes are
harder to resolve than their targeted API microbenchmarks. No source-I/O or other
out-of-scope changes were made.
